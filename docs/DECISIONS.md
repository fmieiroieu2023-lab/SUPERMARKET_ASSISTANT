# Decisions

| # | Date | Decision | Why | Trade-off accepted |
|---|---|---|---|---|
| D1 | 2026-11-04 | Base design = Arena winner (16-agent tournament, 4 rounds) | Most precise plan; every rule has a test case | Over-engineered in places; trimmed below |
| D2 | 2026-11-04 | Web app (PWA) instead of native Expo iPhone app | Avoids €99/yr Apple Developer fee; instant updates; no TestFlight | Weaker barcode scanning, no App Store listing, no widgets. Native app can be added later on the same backend |
| D3 | 2026-11-04 | Online-only (no offline write queue) | Scanning happens at home on Wi-Fi; list is made before shopping | App needs a connection to save changes |
| D4 | 2026-11-04 | Alerts via Web Push (home-screen app) + email digest, sent from the server | iOS supports push for home-screen web apps; server alerts also cover items Claude logs | No alarms scheduled on the phone itself |
| D5 | 2026-11-04 | Build with Claude Code on the Mac; Lovable credits kept in reserve | Backend (SQL, OAuth, MCP) is most of the work and needs full control; Claude usage resets every 5h, Lovable credits monthly | Screens take a bit longer than with Lovable |
| D6 | 2026-11-04 | No custom domain for now | Free `*.pages.dev` and `*.supabase.co` URLs work; domain only needed to email other people or for branding | Digest email only reaches the owner's own address |
| D7 | 2026-11-04 | Budget: ≤ $5/month extra running cost | Owner's constraint | Supabase free tier (pause risk handled by the hourly Worker cron) |
| D8 | 2026-11-09 | Claude is the brain; the app is the visual, tap-based side (browse, confirm, quick actions) | Typing everything is the thing he won't keep doing | Two front doors (app and Claude) must stay in sync: both call the same Postgres functions |
| D9 | 2026-11-09 | Capture = receipt photo first, item photos only when needed (date labels). Barcode scan is optional and later | Consistent habit: one photo per shop | Receipt reading must be good; low-confidence lines are highlighted for review |
| D10 | 2026-11-09 | Expiry modes per category: Ask (date photo) for meat, poultry, fish, bagged salad, fresh dairy, ready meals; Estimate (shown as `~`) for fresh produce, bread, eggs; Quiet for dry goods, tins, drinks, cleaning. Per-user override added in step 4 | Ask only where it matters | Estimates can be wrong; shown as `~` so nobody trusts them blindly |
| D11 | 2026-11-09 | Add flow: the `+` opens the camera → run list ("Mercadona · today · €47.30") → Save. Save writes the purchase (spend) and the pantry lots together. If lines don't add up, Save asks "€2.55 missing, add as unclassified?". Non-food lines count toward spending only | One tap when it adds up; budget always right | One extra tap when a line is missed |
| D12 | 2026-11-09 | Navigation = bottom bar: Home, Pantry, `+`, List, Budget. Recipes and Settings are reached from Home | The bar is the feature list | Fewer things visible at once |
| D13 | 2026-11-09 | Pantry grouped by type (Meat & fish, Fruit & veg, Bread & bakery, Dairy & eggs, Dry goods & tins, Frozen, Drinks, Household), groups sorted by most urgent item. Flagged items: red border + warning mark + the words "Use soon" (never colour alone) | Urgent things on top; accessible | |
| D14 | 2026-11-09 | Look = "Option C · Classic": warm stone background, forest green, brass accent, brick red only for warnings; serif headings (Fraunces) + Atkinson Hyperlegible body; text ≥ 16px, touch targets ≥ 48px; illustrated food tiles with soft 3D tilt and slow, quiet motion (respects reduced motion). Mockup: claude.ai artifact "Supermarket Assistant mockups", board C | Chosen after comparing A (olive), B (glass), D (mono). Readable for all ages | Illustrations: 14 drawn so far; ~200 ingredients still need one each (set to be made consistent later) |
| D15 | 2026-11-10 | Bottom bar becomes Home, Pantry, `+`, List, **Spending** (replaces "Budget" in D12). Spending opens on **Trips** (past shops by month → trip page with its lines, linked pantry items, add forgotten item, fix price, delete); **Budget** is the second view at the top. After Save in the `+` flow you land on the new trip. Recipes have no tab: "Cook tonight" on Home, "Use it in…" on each item, full list from Home | Money in one place; you always see what you just logged | Budget is one tap deeper |
| D16 | 2026-11-10 | Actions happen at once with an **Undo** bar for 6 seconds (no "are you sure?"). The bar stays while you touch it, and the item page keeps the last action undoable until you leave it | Fewer taps, mistakes still safe; 6 s is enough for slower readers without blocking the screen | A missed Undo means fixing it on the item page |
| D17 | 2026-11-10 | Ideas review (artifact "Pantry Idea Review"). **Yes:** Home as a "today" page, full item page, undo, swipe on rows (right = used, left = threw away), pantry search + Fridge/Freezer/Cupboard filters, recipes without a tab, pick receipts from photo library, leftovers as pantry items + a separate **Ready meals & leftovers** pantry group, weekly "Still have it?" cards, which store is cheaper (own receipts only), what the list will cost, Sunday brief from Claude, "Ask Claude" button, count on the app icon. **Maybe:** rescue buttons (Opened / Froze it). **Future, top of list:** forward e-tickets by email. **No:** "same as last time", fridge photo check, cost per portion, in-store mode. **Not answered:** learn from waste, price history screen, own inflation, per-store items | Francisco chose | Price data is still stored with every receipt, so the unanswered money ideas stay possible |
| D18 | 2026-11-10 | App language is English. Product, ingredient and category names show in English first with the Spanish name small underneath (the receipt reader returns both; ingredient English names are the fallback). Search matches either language. Shopping-list items take a quantity and unit (items, packs, kg, g, L, ml); "2 milk" in the add box sets it | Francisco reads English; receipts and shops are Spanish | Two names to keep right per product |
| D19 | 2026-11-10 | Receipt photos are never deleted (they are kept for item recognition). The nightly clean-up only marks unfinished receipt drafts older than 7 days as void and keeps their photos and what Claude read | Francisco: photos are useful training/eval data | Storage grows slowly (~200 KB a receipt) |
| D20 | 2026-11-10 | The shopping list never adds items by itself. The automatic rules (ran out, running low, usual purchase, staples) only fill a "Recommended" banner on the List page; one tap adds | Francisco wants control over the list | The list is only as complete as what you tap |
